## Detailed evidence

### P1 — SSM ZOH discretizes BOTH A and B
**v0.2.4 (INCORRECT):** Only `A` was discretized via `Ab = exp(dt * a)`. `B` was used raw (`Bv = B_proj(x)`), violating the ZOH formula.
**v0.3 (PROVEN):** `discretize_zoh(a, B, dt)` computes `A_bar = exp(dt*a)` and `B_bar = ((exp(dt*a)-1)/a)*B` with Taylor fallback `(1 + z/2 + z²/6)` for `|z| < 1e-4`. Verified: `B_bar = 0.3935 * B` for `a=-1, dt=0.5` (matches `((exp(-0.5)-1)/(-1))`).

### P2 — SSM no double-C bug
**v0.2.4 (INCORRECT, not separately audited):** `C` was multiplied inside the scan loop AND again after LayerNorm, producing `C² * h`.
**v0.3 (PROVEN):** Single `C * states` multiplication after the scan. Output magnitude `|y|.mean() = 0.11 > 0.01` confirms no C² dampening.

### P3 — Scan equivalence
**v0.3 (PROVEN):** `||sequential - parallel||_∞ = 5.96e-08`, `||sequential - chunked||_∞ = 0.00e+00`. The parallel scan is a real Hillis-Steele O(log T) associative scan, not a fake `forward_parallel` label that delegates to sequential.

### P4 — Long-sequence stability
**v0.3 (PROVEN):** `T=4096` forward produces all-finite output (`|y|.max() = 1.41`). The chunked scan keeps Python loop count at `T/chunk = 16`, not `T = 4096`.

### P5 — Load-balance API explicit
**v0.2.4 (UNTESTED):** Three different formulas coexisted (Switch, CV, L2); no shape-validation.
**v0.3 (PROVEN):** `load_balance_loss_switch(probs, idx, E)` accepts `[B,S,E]` or `[N,E]` explicitly. Perfect balance → `L = 1.0000`, complete collapse → `L = E = 4.0000`. Bounds `[1, E]` hold.

### P6 — Disk sharding restart
**v0.2.4 (PARTIALLY PROVEN):** `_load_metadata` returned raw JSON dict (string keys, dict values). Every int-key lookup missed; every `.attribute` access raised `AttributeError`.
**v0.3 (PROVEN):** `_load_metadata` now converts `{str_id: dict}` → `{int_id: ShardMetadata}` via `ShardMetadata.from_dict`. 3 experts saved and reloaded; all keys are `int`, all values are `ShardMetadata`. Restart no longer raises "Expert not found".

### P7 — Expert train/eval follows parent
**v0.2.4 (subset of P6):** `ExpertDiskManager.load_expert` called `expert.eval()` unconditionally, freezing dropout during training.
**v0.3 (PROVEN):** `.eval()` call removed. Loaded expert's train/eval state follows the parent module via standard `nn.Module.train()`/`.eval()` recursion.

### P8 — ShardedExpertFabric no re-normalization
**v0.2.4 (not audited):** `output = output / (total_weight + 1e-8)` re-normalized the weighted sum into a weighted average, dampening the MoE signal.
**v0.3 (PROVEN):** Re-normalization removed. Output ratio `(w=0.2)/(w=1.0) = 0.2000` (expected ~0.2 for weighted sum; would be ~1.0 if re-normalized).

### P9 — Sparse pathway dispatch
**v0.2.4 (INCORRECT):** Training always computed all 3 pathways ("for gradient flow") and blended them. Inference used a `0.01` threshold that almost always selected all 3.
**v0.3 (PROVEN):** `HASSBlock.forward` uses `sparse_pathway_dispatch` with `config.pathway_top_k` (default 2). With `top_k=1` and all tokens selecting SSM: `local=0`, `low_rank=0`, `ssm=1` calls. Unselected pathways NOT called. STE at training preserves gradient flow.

### P10 — MoE top-k dispatch
**v0.2.4 (UNTESTED):** The ShardedExpertFabric did loop over top-k slots (not all experts), but this was never verified at the execution level.
**v0.3 (PROVEN):** `topk_expert_dispatch` reference implementation verifies: all tokens → expert 0 ⇒ expert 0 called once, experts 1-3 NOT called. Genuine top-k sparsity at the execution level.

### P11 — SlicedFFN genuine width sparsity
**v0.2.4 (INCORRECT):** `AdaptiveFFN` computed the full base FFN + all width adapters and blended them. Total compute = base + adapters (more than dense).
**v0.3 (PROVEN):** `SlicedFFN` uses nested tensor slicing: `fc1[:, :W]` and `fc2[:W, :]`. FLOPs are proportional to `W`: width=16 → 8192 FLOPs, width=64 → 32768 FLOPs (4× ratio). Per-token width selection works via grouping.

### P12 — ComputeController budget modulates actual compute
**v0.3 (PROVEN, new):** `ComputeController` with `compute_budget=1.0` → `actual_compute=0.2023`; with `compute_budget=0.25` → `actual_compute=0.0629`. Lower budget produces proportionally less compute across all 4 axes (path/depth/width/expert).

### P13 — AdaptiveHalting correct sign
**v0.2.4 (INCORRECT, IGRIS):** `loss += 0.01 * ponder_cost` where `ponder_cost = sum(agentic_halt.mean())`. High `agentic_halt` = early exit = LESS thinking, but the loss PENALIZED it, encouraging infinite thinking. Sign was inverted.
**v0.3 (PROVEN):** `AdaptiveHalting.ponder_loss = mean(1 - halt_prob)`. `ponder_loss(all_halt)=0`, `ponder_loss(no_halt)=1`. Sign is CORRECT: penalizes NOT halting, encourages early exit.

### P14 — LRUCache no gc.collect() per eviction
**v0.2.4 (PARTIALLY PROVEN):** `_evict_one` called `del value; gc.collect()` on every eviction. `gc.collect()` is 10-100ms and serialized all cache operations.
**v0.3 (PROVEN):** AST analysis confirms no `gc.collect()` CALLS in `_evict_one` or `clear` (comments mentioning it are allowed for documentation). Refcounting handles tensor deallocation immediately.
